Inside the project+

The problem

Useful information was spread across Polish documents. The system needed to retrieve relevant passages and support questions about them while keeping processing within the organisation’s infrastructure.

What I worked on

  • Designed the architecture and developed the local RAG workflow.
  • Combined semantic and keyword retrieval with a reranking stage.
  • Worked on query routing, access permissions, authentication and audit logging.
  • Deployed the system on a GPU server and checked retrieval and answer behaviour.

A key design decision

Semantic search helps with meaning; keyword search helps with exact terms. Combining them, then reranking the results, gives the answer generation stage a more focused set of passages.

Project context

Commercial implementation, 2025–2026. This overview describes my contribution at a high level. Client documents, source code and internal configuration are private.

The problem

Documents arrive in different formats and layouts. The useful content needs to be recognised, classified and turned into fields that other parts of a workflow can use.

What I worked on

  • Designed and implemented parts of the OCR, NLP and LLM processing flow.
  • Worked on classification and extraction using regular expressions, embeddings and language models.
  • Developed comparison logic and tested chatbot behaviour.
  • Collaborated with an architect, project manager and other developers.

A key design decision

Different extraction problems call for different tools. The pipeline combined explicit rules for predictable patterns with NLP and LLM support for less regular text.

03 / Interactive simulationAcademic

MarketSim.
A market you can move.

A browser simulation where orders meet in a limit order book. Change liquidity, place a trade and watch the price and market depth respond.

JavaScriptCanvasChart.js

My role: project design & implementation

From the simulation 03
Try the demo ↗Runs in your browser
Polish interface
Inside the project+

The idea

Make market microstructure tangible. The simulation processes orders from different agents and builds the price history from trades.

What the project includes

  • A limit order book and matching engine with market and limit orders.
  • A market maker, noise traders, trend followers and large orders.
  • Price charts, market depth and a liquidity heatmap.
  • Controls for liquidity, simulation speed and user orders.

How it is built

The JavaScript is split into order book, matching, agent, simulation and rendering modules. The demo runs directly in the browser without a build step. Agent behaviour includes randomness; this is an educational model.

Academic programming project. The live demo uses the public project code with portfolio navigation and responsive layout adjustments.
